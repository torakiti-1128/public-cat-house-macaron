# Cat House Macaron

ブリーダー・里親募集サイトの運営・管理システムです。
一般ユーザー向けの「公開サイト」と、管理者（ブリーダー）向けの「管理システム」の2つで構成されています。

## サイトURL
[https://cat-house-macaron.vercel.app/](https://cat-house-macaron.vercel.app/)

## 概要
本プロジェクトは、猫のブリーディングから里親探しまでを一貫してサポートするWebアプリケーションです。
Go言語によるバックエンドと、Next.jsによるフロントエンドを組み合わせ、モダンなアーキテクチャで構築されています。

## 技術スタック・インフラ

### デプロイ・インフラ
- **フロントエンド**: Vercel
- **バックエンド**: Render (Go Web Service)
- **データベース**: Render（PostgreSQL）
- **オブジェクトストレージ**: Supabase Storage

### バックエンド
- **言語**: Go (1.23.3)
- **アーキテクチャ**: クリーンアーキテクチャ/DDDの概念を取り入れた構成
  - **Repository Pattern**: データアクセスの抽象化
  - **Command Pattern**: HTTPリクエストとビジネスロジックの疎結合化
  - **Service Layer**: ドメインの集約
- **外部サービス連携**:
  - **Notification**: Gmail API, LINE Messaging API (SNS通知)
- **並行処理**: `sync.WaitGroup` や `Channel` を活用したメディアファイルの並列アップロード実装
- **セキュリティ**: `bcrypt` によるパスワードハッシュ化

### フロントエンド
- **ユーザー用**: Next.js 14, Tailwind CSS, Framer Motion (アニメーション)
- **管理者用**: Next.js 15, Material UI (MUI), Axios
- **共通**: TypeScript

## バックエンドのアーキテクチャと特徴

バックエンドの設計においては、拡張性と保守性を重視し、以下の工夫を凝らしました。

### 1. 動的ルーティングとコマンドパターン
エンドポイントの設定を `settings.json` で管理し、実行時に動的にコマンド（ビジネスロジック）を割り当てる設計を採用しています。これにより、新しい機能の追加時にルーターのコードを変更することなく、宣言的にエンドポイントを拡張できます。

### 2. 高性能なメディア処理
子猫の画像や動画のアップロード処理では、Goの強力な並行処理機能を活用しています。複数のファイルをセマフォ（Channel）で制御しながら並列にストレージ（Supabase）へアップロードすることで、ユーザーの待ち時間を大幅に短縮しています。

### 3. 疎結合な通知システム
問い合わせが発生した際、メール（Gmail）とSNS（LINE）の両方に通知を飛ばす仕組みを構築しています。通知インターフェースを抽象化することで、将来的にSlackやDiscordなど、他の通知手段を追加することも容易です。

### 4. 堅牢なエラーハンドリング
並行処理中のエラーを集約して報告する仕組みや、データベースとストレージの不整合を防ぐための整合性管理など、実運用を想定したエラーハンドリングを徹底しています。

## ディレクトリ構造

```text
.
├── backend/            # Go API
│   ├── internal/       # 各ドメインごとのロジック (kitten, parent, auth, inquiry等)
│   ├── commands/       # コマンドパターンの実装
│   ├── config/         # 外部サービス(Supabase, Gmail, LINE)の設定
│   └── routes/         # 動的ルーターの初期化
├── frontend/
│   ├── user/           # 公開サイト (Next.js 14)
│   └── admin/          # 管理画面 (Next.js 15)
```
